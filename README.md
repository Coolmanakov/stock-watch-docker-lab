**Тема №55:** учёт остатков на складе; отдельный веб-сервис рассчитывает критический порог запасов.

## Быстрый запуск

Нужен запущенный Docker Engine и Docker Compose. На macOS проще установить и открыть Docker Desktop. Один файл `/usr/local/bin/docker` является клиентом и сам не запускает контейнеры.

В терминале перейдите в папку проекта, где находится `docker-compose.yml`:

```bash
docker compose up --build -d --wait
docker compose ps
```

Откройте **http://localhost:8080**. Все четыре контейнера должны иметь статус `healthy`. После первой сборки достаточно `docker compose up -d --wait`.

Команды с полным путём также допустимы, если этот клиент видит Compose и использует работающий Docker context:

```bash
/usr/local/bin/docker compose up --build -d --wait
```

Если старый клиент не видит Compose, используйте Docker CLI из Docker Desktop, как описано в [инструкции для Mac](docs/MAC_SETUP.md).

## Как пользоваться

1. Нажмите **«Загрузить склад»**: backend прочитает товары из PostgreSQL.
2. Нажмите **«Проверить запасы»**: backend отправит снимок товаров в `web-service`, получит расчёт и сохранит проверку в БД.
3. В начальном наборе USB-C кабель ниже порога, мышь на пороге, блок питания имеет достаточный запас.
4. Измените остаток USB-C кабеля с 12 до 80 через «Изменить» → «Сохранить товар», затем снова проверьте запасы.
5. Добавьте свой товар, проверьте его, при необходимости удалите. История проверок хранит снимки и не меняется при редактировании или удалении товара.
6. «Загрузить историю» читает последние 20 проверок из PostgreSQL.

Данные учебные. Расход считается постоянным:

```text
порог = расход_в_день × срок_доставки + страховой_запас
целевой_запас = порог + расход_в_день × 7
```

Остаток ниже порога — `critical`, равен — `warning`, выше — `ok`. В первых двух случаях рекомендуемый заказ равен `max(0, целевой_запас − остаток)`; в последнем — 0.

## Четыре контейнера

| Сервис | Технология | Назначение |
| --- | --- | --- |
| `frontend` | Nginx, HTML/CSS/JS | Интерфейс и проксирование `/api/` |
| `backend` | Python 3.12, Flask, psycopg | REST API, CRUD, сохранение проверок |
| `db` | PostgreSQL 16 | Товары и история проверок |
| `web-service` | Python 3.12, Flask | Расчёт порога и рекомендуемого заказа |

Все сервисы подключены к `lab-net` с драйвером `bridge`. Только frontend публикует порт хоста: `127.0.0.1:8080`. Внутри сети backend обращается к `db:5432` и `web-service:8001`, frontend — к `backend:8000`. Внешний API и ключи не нужны. Интернет необходим при первой загрузке образов и Python-зависимостей; работа собранного приложения не требует внешнего API.

Backend ожидает готовность db и web-service, frontend — backend. Все сервисы имеют healthcheck. БД инициализируется тремя товарами из `db/init.sql` при первом создании volume. Данные хранятся в именованном volume `stock-data`.

## Остановка и сохранность данных

```bash
docker compose down
docker compose up -d --wait
```

Обычный `down` удаляет контейнеры и сеть, но сохраняет volume. Товары и проверки остаются. **`docker compose down -v` удаляет данные**, поэтому для демонстрации сохранности не используйте `-v`. Повторное выполнение `init.sql` происходит только при создании нового пустого volume.

## REST API

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/products` | Товары из БД, 200 |
| POST | `/api/products` | Создание товара, 201 |
| PUT | `/api/products/{id}` | Обновление всех полей товара, 200 |
| DELETE | `/api/products/{id}` | Удаление товара, 204 |
| POST | `/api/analysis` | Расчёт через web-service и сохранение снимка, 201 |
| GET | `/api/analyses` | Последние 20 сохранённых проверок, 200 |

Пример создания:

```bash
curl -X POST http://localhost:8080/api/products \
  -H 'Content-Type: application/json' \
  -d '{"name":"HDMI кабель","quantity":12,"daily_usage":5,"lead_days":3,"safety_stock":5}'
```

Ошибки API возвращают JSON с `error`: 400 — неверный ввод, 404 — товар не найден, 409 — лимит 1000 товаров, 502/504 — сбой/таймаут расчётного сервиса, 503 — сбой БД. SQL использует параметры. На frontend пользовательский текст вставляется через `textContent`.

## Настройка

Можно скопировать `.env.example` в `.env`, изменить `FRONTEND_PORT` или учебный `DB_PASSWORD`. Файл `.env` не публикуется. Значения по умолчанию позволяют запустить проект без дополнительных файлов. Пароль по умолчанию предназначен для этой локальной лабораторной. При существующем volume смена переменной пароля не меняет пароль пользователя PostgreSQL: для учебной демонстрации оставьте его без изменения.

## Проверки

```bash
python3 -m pip install -r backend/requirements.txt -r tests/requirements.txt
python3 -m pytest -q tests
```

После запуска контейнеров можно проверить реальную цепочку Nginx → Backend → Web-service/PostgreSQL:

```bash
python3 scripts/smoke.py
```

Скрипт создаёт временный товар, проверяет расчёт и сохранение истории, меняет остаток и удаляет временный товар. Две проверки остаются в истории.
